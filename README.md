# BCX website: bcx.market

The public website of **Bharat Coal Exchange**: the company pages, plus **Market Insights**, India's coal
market from official sources (production and offtake, plant coal stocks, the coal map, coal in electricity,
e-auctions).

This repository holds **only the website**. It does not contain the studio, the newsletters, ULIP fleet tracking
or the exchange demonstration. Those stay in GNA's private coal-platform repository.

## Layout

```
web/                     THE SOURCE: edit here
  index.html             the page (robots tag from VITE_ROBOTS: indexed in production)
  src/main.jsx           entry: theme before first paint, then <Website/>
  src/Website.jsx        router, header, footer, page transitions
  src/website/           every page and component (Insights, CoalMap, coalmap/, mines/, charts, ui…)
  src/website*.css       styles; website-dark.gen.css is GENERATED (npm run dark-css)
  public/site/           photographs and the favicon (served at /site/…)
  public/CNAME           bcx.market
  scripts/check.mjs      the site's rules, run before every build
  .env / .env.production where the API is (VITE_API_BASE) and whether crawlers may index (VITE_ROBOTS)

index.html assets/ site/ CNAME robots.txt .nojekyll
                         THE BUILT SITE: GENERATED by the workflow, served by GitHub Pages. Never edit by hand.
.github/workflows/build.yml   builds web/ and publishes the build at the root
```

## Architecture

```
  visitor ──► bcx.market ──► GitHub Pages ──► this repository's root (the built site; main, "/ (root)")
                (GoDaddy DNS, unchanged)
     │
     └─ the page fetches its figures ─► https://bcx-newsletter.gna.energy/api/website/*
                                         CloudFront → GNA's on-prem cluster → the coal platform's API
                                         public, read-only, CORS * (no cookies, no login)
                                                │
                                                └─ the serving DB, refreshed six times a day by the
                                                   platform's bcx-site-data job (CMPDI, Coal India, CEA,
                                                   Grid-India, Ministry of Coal…)
```

- **The site is static.** The address bar uses hash routes (`#/insights/supply`), so no server-side routing is needed.
- **The figures are live.** Every page reads the platform's website API. These are the only calls it makes, and
  `scripts/check.mjs` fails the build on any other:

  | Call | Serves |
  |---|---|
  | `GET /api/website/market` | every figure, board and series (about 1 MB, cached in the browser and revalidated) |
  | `GET /api/website/coalmap` | the coal map |
  | `GET /api/website/coalmap/plant/<id>` | one plant's history |
  | `POST /api/website/visit` | one visit per browser session; production builds only |
  | `GET /api/website/visits` | the visit counter |
  | `GET /api/website/issues` | the newsletter archive, read only while the newsletter is on (local only) |

- **The visit counter is bcx.market's own.** The API stores each visit with the site it came to (the browser's
  `Origin`) and counts bcx.market separately. It started at 0 on 16 Nov 2026.
- **Where the API is** comes from `VITE_API_BASE`: `web/.env.production`, or the repository variable `API_BASE`.
  Empty means "this page's own server": the dev server proxies `/api`.
- **No secret is needed anywhere.** The API is public and read-only, and the build holds no keys. This
  repository is public: keep it that way, and never commit credentials (`scripts/check.mjs` looks for them).

## Run it

```bash
cd web
npm install
npm run dev                                                   # http://localhost:5180, API from a local backend on :5001
BCX_API_TARGET=https://bcx-newsletter.gna.energy npm run dev  # the same, reading the live data
npm run build && npm run preview                              # the production build, reading the live API
```

## Deploy

**A push to `main` that changes `web/` deploys bcx.market.** The workflow:
1. builds `web/` and runs the checks;
2. confirms the API answers;
3. commits the build to the repository root (`build: bcx.market from <sha>`);
4. asks GitHub Pages to publish it.

The site is live a minute or two later.

Nothing else is involved:
- the Pages setting stays "Deploy from a branch: main, / (root)";
- the custom domain stays `bcx.market`;
- the DNS stays at GoDaddy, MX and email included.

## Rules that travel with the site

- **The newsletter is local only.** It shows on the dev server and in no build that ships, until the
  owner says "deploy newsletter" (`web/src/website/flags.js`; checked).
- **No ULIP data.** ULIP's data may be shown only behind a login, and this site has none.
- **Figures as published.** No interpretive prose. Every comparison is computed by the API, never in the browser.
- **A switch never moves a control.** Panels keep one height whatever is chosen.
- **The dark theme is generated.** After any edit to `web/src/website.css` or `website-bands.css`, run
  `npm run dark-css` and commit `src/website-dark.gen.css`.
- **Every photograph carries its credit** (`web/src/website/media.jsx`).
